# 法规合规审查模式对齐候选 v1

状态：供用户审阅；**未启用、未替换正式 prompt、未改运行代码、未触发在线推理**。用户提供的《合规审查模式》是设计参考，不因文件标题而获得运行时 system 指令权限。对照基准为 `phase2_public/prompts/system_prompt_final.md` 与当前整包候选代码。

## 1. 判断

新模式最有价值的是将“适用规则 → 可验证命题 → 文件事实 → 要件对照”明确放在结论之前。这可成为现有**文档关键词发现**的前置规则清单与范围闸门，避免把普通技术标、清单、施工方法叙述直接路由为法律风险。但新模式还只是方法提纲，不能直接替代既有 Level 1→4、来源准入、定位、LLM/gate 与任务契约。

现有机器只能就已入包、成功解析、成功路由的事项形成有限初审；“逐项”必须有可审计分母：`适用规则项 → 应查文件/页面 → 已查事实 → 未读/未配对/不适用/已处理`。原始关键词候选数不是规则项数、独立事项数或发现召回率。

## 2. 逐步校对

| 新模式步骤 | 正式 prompt / 当前代码 | 候选处理 |
|---|---|---|
| 1. 项目地点、方式、阶段、版本、适用日期 | prompt 有时空适用性规则；manifest 只记录部分上下文，文件版本/补遗仍可能未确认 | 建立可定位的项目契约；决定性条件未知时不默认强制招标或“已发出最终版本” |
| 2. 建依据清单 | 现有 Level 1→4 法规库和 S 标准分类；投标响应路线另用招标要求 | 必须标注依据角色：法规、正式标准、招标要求、合同约定、内部制度；后四者不得自动升格为法规 |
| 3. 验地域、时间、主体、前提 | prompt 与法规 gate 已要求，但地方/历史版本 metadata 完整度仍是约束 | 在原子命题级记录适用性和反向证据；“没有命中法条”不等于不适用 |
| 4. 拆单一可验证命题 | 当前 `bundle_review.py` 用宽泛关键词选 block，尚无完整规则拆分 | 作为最优先的离线新模块；分离义务、主体、条件、例外、时限、阈值和证据需求，保留原条文 locator |
| 5. 在文件定位事实 | 已有原文件哈希、block/页面 locator、OCR 质量及部分配对 | 再区分正式投标陈述、招标格式模板、法规转述和实际履行记录；不能把模板中“禁止串标”当作本案串标事实 |
| 6. 要件、遗漏、反向证据 | 法规推理与配对各有 route；现行配对只是有限文本比较 | 同一命题同时找支持与反证；未见材料须区分“已核完整文件包确认缺失”与“输入/解析/检索未见” |
| 7. 结论、等级、整改、复核 | 正式 prompt 有 canonical 结论和 gate，Excel 已有部分字段 | 保留现有状态及原始/gate留痕；风险等级、处理优先级、人工签发须与实体结论分列 |

## 3. 依据角色及任务分路

1. **法规性合规命题**：在项目阶段/辖区/时间内适用的 Level 1→4 独立法规要求，与招标或投标事实比较；技术标准只有在其独立身份、适用性及相应义务来源可验证时，才进入单列的标准审查路线。
2. **招标要求—投标响应命题**：依据是有效招标文件及正式补遗，结论只关于已供文本的实质性响应差异；不是自动违法、废标或中标结论。若要质疑招标要求自身是否合法，另建法规性命题。
3. **合同、清单、内部制度/技术质量命题**：默认属于辅助一致性或专业核算，不进法律 RAG 的合规结论。只有明确的法规桥接或招标实质性要求，并且任务阶段匹配时，才可重新准入。不能整份排除技术标，因为其中个别条款仍可能承载法定义务。

建议将现有规则发现做成**两条互补但不混淆的入口**：

- `rule_first`：从已准入法规及有效招标要求抽取原子命题，再到文件中检索支持、冲突和缺失证据。这是计划的核心入口。
- `document_first_exception`：保留轻量文档异常发现，用来捕获自相矛盾、意外的否决约定或规则清单遗漏；只有能够回配到适用法规或实质性招标要求，才可形成合规 finding。纯技术、清单算术和不在当前阶段的事项留为辅助/范围外记录。

规则清单只覆盖其已记录来源、版本、辖区和审查主题；**不能把本地库规则清单未列某项等同于法律不存在或项目合规**。外部检索是否补充规则、补充到了哪一条及准入结果仍须单独记录。

范围分类至少为 `legal_compliance / material_bid_response / auxiliary_nonlegal_not_reviewed / scope_uncertain`，同时记录 `rule_id`、任务阶段、输入来源、准入原因和排除原因。范围不确定不得默认为风险、无风险或不适用。

## 4. 结论不能直接使用同一扁平枚举

用户参考文件的“符合、不符合、证据不足、不适用、需专业复核”混合了**实体比较、规则适用性和工作流状态**。建议拆成三轴，避免通过改词提高所谓一致率：

| 轴 | 推荐表示 | 与现行状态的关系 |
|---|---|---|
| 规则适用性 | `matched / not_applicable / uncertain`，附地点、时间、主体、例外和版本依据 | `not_applicable` 仅在条件已核实时成立；不是“未检索到”或“未处理” |
| 有限审查结论 | `supported_potential_issue / no_supported_issue_within_scope / insufficient_information / not_reviewed_or_blocked` | 对接既有法律 canonical 状态；未经独立事实—法规确认不得直接输出“违法/不符合” |
| 人工交接与签发 | `review_required / ready_for_review / not_signed_off / signed_off` | “需专业复核”不是实体结论；每一项初审仍须人工最终签发 |

风险严重程度和 P0/P1/P2 工作优先级是额外字段，不是上述任一轴。投标文本 `textually_consistent` 只表示两个指定片段在比较范围内相符，不能被翻译为全面“符合”。

## 5. 尚缺的运行约束与守护例子

参考文件未覆盖：四层级联停止条件、官方外检实际调用与条款级来源准入、原始响应与 post-LLM gate、已审包确认缺失和仅在当前输入未见的区别、OCR 页/补遗/未配对事项的未处理分母、作用阶段及例外、自动外发隐私边界。这些继续沿用或补建，不能被短版模式省略。

离线守护至少包括：

- 技术标段落只有“应加强质量管理”，无法规要件/招标实质性要求：**不进法规推理**，也不记项目合规。
- 投标模板转述“借用资质投标属于违法”：不是投标人实际借证的证据。
- 清单条目、价格求和、单位换算：不因含“报价”进入法律结论；另列造价计算能力。
- 招标文件设定投标保证金、资格或否决条件且可定位：即使尚无投标人违约事实，也可检查**该招标规则本身**的法规适用性。
- 有适用法规但 OCR 缺关键数值、或补遗版本未确认：已可回答的子结论保持，决定性缺口单列 U；技术失败单列 blocked/not_run。
- 可适用地方条文必须匹配工程地点、类型和适用时间；只发现网页标题不能作为已准入法律依据。

## 6. 推进顺序与评价

先冻结现有整包输出，另建离线 `rule_inventory + scope_gate` 候选；不重写旧候选或旧实验。使用一小批人工核验的**法律/实质性响应/技术清单/模板转述/范围不确定**样本评估误准入与误排除，优先确保法定义务不被误排。然后再测原子命题定位、跨文件配对、法律依据适用性、风险/弃权及未处理覆盖。原始候选总数缩小本身不是效能提高；真实召回率需要独立建立应审事项清单。通过离线守护并获用户批准后，才重选在线小批，现有未发送事项不自动继续。
