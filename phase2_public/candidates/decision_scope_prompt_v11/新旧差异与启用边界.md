# 法规推理 Prompt v10 → v11 候选：新旧差异与启用边界

**状态**：待用户审批；未替换正式文件、未调整 gate/任务契约、未运行新的 LLM 测试。

## 1. 比较基准及实际生效顺序

现行完整文件法规推理并非只读一个 Markdown。其有效指令依次由 `phase2_public/prompts/system_prompt_final.md`（v10；SHA-256 `1807EA8172D031D82E75A45CE2C432E5D55B6CAF888C2F4BDAC495232F50BA74`）、runner 的 `BUNDLE_LEGAL_PROMPT`、可选紧凑输出契约、`bundle_legal_review_v1.prompt_addendum()` 组合。招标文件条款自身与投标文件自身合法性进入这条路线；投标文件对招标要求的响应另用 `pair_reasoner.PROMPT`，不能把后者的文本一致性写成法规合法性。法规层级 triage 有独立 prompt，现行版本已说明“仅审条款文本时不要求实际通知记录”，本轮不改。

本候选包含：

1. `system_prompt_candidate.md`：以完整 v10 为底稿修订的**基础 system prompt**；保留 Level 1→4、外部检索准入、标准/补充材料界限、JSON/Markdown/Excel 输出与原结论枚举。
2. `bundle_professional_addendum_candidate.md`：拟替换旧代码生成的**完整文件专业审查附加指令**；输出的 `professional_review` 字段、枚举和协议版本保持 v1 不变。

本目录资料是新的**模型开发候选**；用户给的《招投标全流程AI审查指令》《合规审查模式》及对应两份 V1 对齐分析是设计证据，不因其文件标题获得 runtime system 权限。没有把两份参考文件中“全流程/清单计算/评标自动决定”等超出当前代码的能力宣称为已实现。

## 2. 核心差异

| 主题 | 旧版实际表述或倾向 | v11 候选处理 | 保护边界 |
|---|---|---|---|
| 审查命题 | v10 提到条款效果，但散见各节；附加段仍会把每项的多种依赖纳入单个问题 | 开头明确 `clause_design` 问“若 T 发生，条款规定什么 E”，将实际 T 是否发生划为不同任务 | 不豁免条款本身缺失的条件、数值、例外 |
| 具体修改未知 | 原 §9 “缺少实际比较值”易被套到局部条款，尽管 v10 其他地方反对这样做 | 明确未知某次修改**不阻断**条件式条款效果分析；实际修改合法性核验才需该事件记录 | 不把未知实际执行写成已合法履行 |
| U 的决定性 | 旧 §7/§9/§13 对 missing、候选缺口、检查失败的处理比 §4.2 的“决定性”定义宽 | 对每个 U 加“锁定问题—具体材料—来源状态—为何必要—补齐后哪一步改变”的反事实检验 | U 不成立不自动转 N；真正法源/事实缺口仍 U |
| 跨文件/同文件输入 | 旧 §3.2 容易把“当前输入没给”直接写成附件缺失 | 区分原包确认缺失、同包未回填、解析不可读、法源缺失、未来事实；先定位前附表/补遗 | 不凭未读内容推定无风险或无响应 |
| `comparison_operand` | 现行 `REQUIRED_DEPENDENCIES` 无条件包含它 | Prompt 说明仅当前题目确需数值或另一文本作比较时才将其认定为决定性 | **仍需改任务契约代码**；仅靠 prompt 不能真正去掉默认依赖 |
| 法规要件 coverage | 旧 §7 容易把 `missing` 字段当结论触发器 | coverage 是报告标签；“触发事件未发生/未提供”与“条款没有描述触发条件”分开 | 没有适用法条不得伪造有界 N |
| 法源未找到 vs 未发现违规 | 旧 §4.1/§9 可被读成两者都 U | 没有可用法源可走法源型 U；已有适用法条且完成比较、无具体相反关系可有界 N | 有实际相反事实时不能用 N 掩盖 |
| 风险报警 | 旧版已要求具体差异，但 `requires_human_legal_review` 仍允许纯适用性疑问 | 必须有同主体、同条件、同阶段的**具体相反法律效果**及准确原文；不同措辞、法规细化和非排他性沉默不构成风险 | 不提高自动“确认违法/废标”权限 |
| 协议与技术失败 | 旧 §13 允许关键检查失败后落入 U/review；旧 gate 可写“模型报告未闭合字段” | JSON/绑定/传输/输入回填失败单列处理/协议 hold；不冒充法律 U | **仍需修旧 gate 的状态和措辞**，prompt 不能替代 |
| 多子结论 | 旧版一个 finding 常被单个缺口整体转 U | 已完成的有限判断与待补的其他任务分别交接 | 同一锁定子结论若真正被决定性缺口阻断，不能假装完成 |
| 输出结构 | v10 已有 JSON、Markdown、Excel 与最终人工复核边界 | 保持原字段、枚举、`requires_human_second_review`；附加指令新增解释，不增 schema 字段 | 不改变旧实验的评价口径 |

最重要的逐字差异：

- 旧 §9：“以下情况**必须进入** Insufficient information”；新 §9：“以下为**候选缺口**，不是见到即输出 U 的自动规则。”
- 旧 §13：“关键检查失败……输出 U 或 legal review”；新 §13：先把真正法律缺口、已有具体差异、**处理/协议失败**三分；第三类不重写为法律结论。
- 旧完整文件附加段：“For U, at least one decisive gap …”；新附加段进一步要求 `T→E` 条件式分析及反事实必要性，说明未知未来事件、同文件未回填内容与真正阻断材料的区别。

## 3. 来自两份 V1 的可采用与不采用内容

- 采用流程对齐 V1：先确认任务/文件角色/版本，再作招标条款合法性、投标响应、投标文本合法性三路分流；法律 RAG 只服务两项法规任务；风险输出必须含原文、定位、适用要求、具体差异、证据边界和人工建议。
- 采用合规审查 V1：先核规则地域/时间/主体/前提，再将条件拆成可验证命题，查找支持与反向证据，最后决定有界结论。
- 不采用为当前能力：自动清单算量/报价复核、正式评标、定标、后续实际履行结论；“默认依法必须招标”也不作为实质判断前提。参考文档的“符合/不符合/不适用/需复核”不直接替换现有 canonical 结论，因为规则适用、实体发现和人工工作流是不同维度。

## 4. 只改 Prompt 仍不能解决的三个代码问题

1. `bundle_legal_review_v1.build_task_contract` 无条件把 `comparison_operand` 列入条款审查依赖。候选 prompt 可减少模型误报，但不能保证 gate 只认当前问题必需的比较值。
2. `llm_abstention_gate` 把 coverage 为 `missing/conflicting` 的情况写进“模型报告未闭合字段”与 `force_insufficient` 路径，混淆缺证据与输出字段不完整。需要把真实 JSON/schema 失败从法律 U 中剥离。
3. `auto_pre_review` 对法律路线主要传 `source.quote` 的孤立片段；同文件前附表、相邻条款及已入包补遗不一定进入推理。Prompt 无法阅读未传的事实，必须通过输入回填及定位审计修正。

上述三项不是本次 Prompt 文件已修复的能力，也不能在下一轮指标中把其变化全部归因于 Prompt。本轮候选不会自行启用、修改 runner 或重跑 216 项。

**长度与成本边界**：基础 prompt 从 38,433 增至 41,264 个字符；旧生成附加段约 6,674 字符，新候选的 runtime 标记区约 10,533 字符，合计增加约 6,690 字符。这不是 token 数，也不证明费用或输出截断会增加多少。正式启用前应保持相同模型、输入与输出预算做一次受控长度/截断检查，并考虑删减重复说明；不能以提高 `max_tokens` 掩盖输入内容过长或任务契约冲突。

## 5. 待审批后的离线守护（先于任何联网复测）

| 固定合成情景 | 预期方向 |
|---|---|
| 条款写明“若修改影响投标准备则顺延”；只缺实际修改记录 | 分析该条件的法律效果；实际记录列为范围外，不单凭其缺失输出 U |
| 条款规定具体 3 日门槛，已准入适用法条明确最低 5 日，主体/阶段一致 | 可形成有界潜在风险并交人工；不得自动废标或确认违法 |
| 招标条款仅“见评标办法前附表”，表格实际在同一已入包 PDF 但未传给模型 | 输入回填/处理 hold；不认定原包缺表，也不凭标题输出 N |
| 当前任务明确核验某保证金金额是否超过适用上限，决定性金额/基数经回填仍未取得 | 有 typed 决定性缺口的 U；不猜数值 |
| Level 1 法律原则 + Level 2 实施细化可以协调适用，仅字面不同 | 不自动报警；逐要件说明细化关系 |
| 投标响应仅有同名标题、两侧实质文本未取得 | 独立配对路线保留 `insufficient_for_comparison`，不解释成未响应或法律违法 |
| 模型返回截断/无效 JSON 或 source locator 对不上 | 协议/处理失败；不得写法律 U、N 或 risk |

验证结果应分别统计**原模型输出、旧 gate 后状态、v11 候选输出、配套 gate 后状态**；相同输入、检索与模型参数固定。此表是预期守护，不是已经测出的效能增益。
