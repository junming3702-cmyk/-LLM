## Changes

1. A single executable schema supplies field descriptions, required fields,
   allowed values and dependency/kind combinations to prompt generation and
   structural validation. Both complete synthetic examples use that validator.
2. Completed checks require a name and comparison, along with explicit check
   type, claim IDs, legal IDs and exact quotation/locator. Text observations
   cannot establish independent legal conclusions.
3. Gap material type no longer uses "outside question". Relations are explicit;
   dependency triggers distinguish locked requirements, specific observed context
   conflicts and generic uncertainty. The latter is not automatically legal U.
4. Ambiguous, mixed, undeclared or contradictory relations are routed to scope
   review. No valid legal verdict is emitted for that state. Core decisive gaps
   cannot be waived by false flags or empty claim lists.
5. Mechanical normalization is opt-in and audited. Only unambiguous field-name
   aliasing and enum case/whitespace are allowed. Missing fields, bad quotations,
   wrong dependency types and semantic inconsistencies remain unresolved.
6. Review handoff and display distinguish structure/evidence failure, scope
   review and valid legal answerability. Prior raw responses are retained.
7. Real-case data, expert scores, research drafts and credentials are excluded
   from this public candidate. Existing production defaults are not changed.

## Evaluation dimensions

Report separately: transport/parse availability; raw decision_basis protocol
conformance; normalized protocol conformance; schema/evidence/scope delivery
holds; bounded legal labels only for valid delivery; and human adjudication.
The protocol denominator includes unsuccessful parses, not just successful JSON.
For multi-finding outputs report both response-level and finding-level counts.
Do not call software test pass rates legal accuracy, Recall@5, MRR, or handoff
effectiveness. This candidate has not been tested in new online inference.

## Limits / no auto-promotion

Typed explanations and exact source pointers do not prove legal entailment or
that a stated dependency is truly decisive. Text-pattern safeguards recognize
some mixed dependencies, not all natural language. Human scope review remains
necessary. Old v4 responses must not receive fabricated v4.1 fields and then be
reported as new observations. Input-context supplementation is a separate
intervention, using a separately versioned input with unchanged other factors.
Keep legacy outputs, raw failures and input hashes immutable.
